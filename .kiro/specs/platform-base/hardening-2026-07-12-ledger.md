## 3. Hai regression đã khắc phục tận gốc (V0 — AI Kiro fix)

### FIX-1 — Build gãy CA1861 ở migration mới → `.editorconfig generated_code` (AD-070)
- **Triệu chứng:** `vp build` FAIL — `CA1861` tại `Identity.Infrastructure/.../Migrations/20260712055600_AddOutboxClaimLease.cs(32)` (composite index `columns: new[]{...}` EF sinh; `TreatWarningsAsErrors=true`).
- **Root cause:** `platform/.editorconfig` THIẾU luật miễn analyzer cho code sinh migration (trong khi `starhill/.editorconfig` đã có — QR-AD-009). Migration là code sinh tự động; sửa tay mảng thành `static readonly` = fragile (mất khi `dotnet ef` regenerate) = fix ngọn.
- **Fix:** thêm `[**/Persistence/Migrations/*.cs] generated_code = true` (mirror QR-AD-009) → analyzer bỏ qua migration; future-proof mọi migration sau. Bằng chứng: sau sửa `vp build` = 0-warning.
- **Journal:** AD-070.

### FIX-2 — Regression JWT key-ring (A-18 làm dở) → đăng ký IDEMPOTENT chia sẻ (AD-071)
- **Triệu chứng (3 lớp nối tiếp, verify từng vòng qua `vp all`):**
  1. `HostSmokeTests` 2 fail — `IDX10703 key length zero` từ `JwtTokenService..ctor` (nhận key-ring rỗng).
  2. Sau sửa lần 1: `Bedrock.Api.Tests` 10 fail — `No service for JwtKeyRingOptions` (Api dùng độc lập, không có AddBedrockSecurity).
  3. Sau sửa lần 2: `HostSmokeTests` 3 fail — `JwtKeyRingOptions có Kid trùng: dev` (double-bind list Keys).
- **Root cause kép:**
  - (a) AI đợt trước thêm `services.TryAddSingleton(keyRing)` với `keyRing` bind EAGER lúc registration ở `AddBedrockAuthCore`. Nhưng secret nạp MUỘN (User-Secrets/env/test-inject) → eager chụp rỗng. Vì `AddBedrockApi`(AuthCore) chạy TRƯỚC `AddBedrockSecurity`, instance rỗng thắng, SHADOW instance lazy đúng → sign+verify nhận key-ring rỗng.
  - (b) Khi cho cả hai composition cùng `AddOptions<JwtKeyRingOptions>().Configure(Bind)` → config binder APPEND list `Keys` 2 lần → 2 key `dev` → validator "Kid trùng".
- **Fix (bản chất):** đăng ký binding + concrete `JwtKeyRingOptions` **IDEMPOTENT** — guard `services.All(d => d.ServiceType != typeof(JwtKeyRingOptions))` ở CẢ `AuthCore` lẫn `AddBedrockSecurity`; bind **LAZY** qua `AddOptions().Configure(Bind)` (thấy config nạp muộn — F35); `ValidateOnStart` + validator do sign-side (Security) sở hữu. Kết quả: đúng MỘT lần bind → sign (JwtTokenService) + verify (JwtBearer) CHIA SẺ CÙNG instance đã validate (đạt A-18 THẬT), và `Bedrock.Api` vẫn dùng độc lập được (verify-only).
- **Bằng chứng:** sau fix `vp all` = 248 test / 0 fail (StarHill.Api.Tests 3/3, Bedrock.Api.Tests 40/40).
- **Journal:** AD-071 (REFINES AD-008 điểm-chung-ký/verify, AD-045 validate-on-start).
